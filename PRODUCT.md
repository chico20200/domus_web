## Platform

web

## Users

- **Coordinador** (stored as `admin` in code until the migration in ESPECIFICACIONES §9.1): creates and configures a caja, invites members, and can also record every operation a tesorero can. Works mostly on a computer.
- **Tesorero**: records socios, savings, credits, payments and reports for one caja. Works mostly on a computer, often keying in data for socios who have no device.
- **Socio**: looks up their own savings accounts. Phone first.
- **Administrador del sistema** (system scope, not yet built: HU019/HU020): oversees cajas and accounts with counts only, never amounts.

Users generally have no financial training. Every action that moves money or changes a caja must be understandable before it is executed.

Roles are per caja: one account can be coordinador in one caja and socio in another.

## Product Purpose

DOMUS is the treasury system for community savings banks (cajas de ahorro comunitarias). It digitizes the registry of socios, savings and credits, and automates calculating and distributing interest among socios when each cycle closes.

Current goal: the Trabajo de Integración Curricular (TIC) at Escuela Politécnica Nacional, ESFOT (2026), judged through the directora's reviews and the usability tests in ESPECIFICACIONES §11. After that it is meant to serve real cajas, so decisions should hold up for real use and not only for the defense.

Success means a person without financial training can create a caja, register socios, and run savings, credits and payments correctly, understanding each step. It also means the system and the thesis document describe the same thing in the same words.

## Positioning

One instance serves many cajas, each isolated from the others (multi-caja), with roles scoped per caja. Interest distribution at cycle close is automatic and explained, not a spreadsheet the tesorero maintains by hand.

## Operating Context

- Cajas are real community organizations that run in cycles. A cycle is the period between account cuts, and its founding date may predate registration in DOMUS.
- The coordinador or tesorero registers a ficha de socio on someone's behalf. A ficha links to a user account when the email matches.
- Credits are granted only between socios of the same caja and use simple-interest amortization. Payments can be the full installment, interest only or capital only (abono, prepago).
- Joining a caja happens through an invitation code generated by that caja's coordinador. The code determines the role on entry.
- Demo deployment: https://domus-online.netlify.app (frontend on Netlify, backend on Render).

## Capabilities and Constraints

- Modules: Autenticación, Cajas, Socios, Ahorros, Créditos, Pagos, Reportes, Ciclos.
- Stack: React 19, TypeScript, Vite, Tailwind CSS 4, React Router 7; Node.js, Express, JWT; PostgreSQL on Supabase.
- Role ladder `socio < tesorero < coordinador`, with inclusion in one direction only (decided 11 Nov 2026).
- `docs/ESPECIFICACIONES.md` is the source of truth for the refactor and its stage order (§12). Work proceeds one stage at a time.
- Out of scope and slated for removal: donations/PayPal and the chatbot (ESPECIFICACIONES §7).
- Open decisions (ESPECIFICACIONES §13): real row-level security vs. documenting filter-based isolation; the five-cajas-per-account limit; whether the notifications icon is implemented or removed; "Bloqueado" vs. "Suspendido" as the account-state name.

## Product Principles

1. **Understand before acting.** Any action with money or caja-wide consequences explains what it is, what happens, and what is needed first, and it works by tap, not hover.
2. **One language.** The same concept, amount or date looks and reads the same on every screen and in the thesis.
3. **The role decides what is visible.** Each role sees and can reach only what it is allowed to do, and the coordinador can do everything a tesorero can.
4. **Isolation is a promise.** Nothing from one caja is visible from another, and the interface never implies otherwise.
5. **Honest over aspirational.** The interface and documentation describe what the system actually does.

## Accessibility & Inclusion

- WCAG AA contrast in both light and dark mode.
- Every form can be completed with the keyboard: Enter submits, Tab follows visual order, Escape closes modals (HT01).
- Help panels open on tap, not hover, because socios use phones.
- Plain language for users without financial training.
